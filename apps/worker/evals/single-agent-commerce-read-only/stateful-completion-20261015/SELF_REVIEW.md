# Stateful B completion: self-review before provider work

Reviewed the current contract, existing transaction, native tool bridge, candidate ingress/session, private checkout and capture runner together. This is primary-agent review, not independent acceptance. No owner/verifier prompt, model, historical population or score is changed.

The owning gap was that one persisted mutation consumed the Inbox lease before a second mutation or final reply. The existing transaction now optionally retains the current lease for an intermediate commit. The default remains completion. Retention requires the current Inbox guard and forbids a Meta plan; every subsequent write still locks/rechecks that guard, conversation revision, sales revision, source-bound native permission and exact replay evidence. No new table, migration, operation store or state machine is introduced.

The native permission contributor is internal code authority for the existing typed commands. The model supplies bounded product/line references and requested values, never source identity, recipient, permission, command hash or receipt. Variant changes use the current offer and source-selected exact SKU. The existing mutation engine and database replay check the resulting cart. Public context exposes current cart references and checkout completeness, not private checkout values.

Observed RED and minimum GREEN cover native variant evidence, retained lease, unchanged-cart readback, current generation after source completion, current committed handoff, accepted native-cart receipt after prerequisite transitions, source stock projection, canonical SKU casing, private message exclusion and private clarification. Real-database intermediate reports remain preserved, including failures. They exposed a cart-open validator wrongly assuming the cart event was the first event; the existing ordered event-envelope validation already owns that invariant, so the redundant check was removed. They also exposed stale inherited handoff authority, private payload readiness, and returning send eligibility after a superseded transaction; each was corrected at its existing boundary.

The latest database regression changes a component SKU after verifier PASS while price and quantity stay equal. The candidate now reuses `selectionsMatchCartLines` at final Outbox eligibility and closes the source without sending on mismatch. The same existing comparator is reused for selection evidence in context, including the mutation engine's NFC/uppercase normalization. A focused RED showed that uppercase-only comparison previously dropped evidence for an equivalent SKU spelling; focused GREEN follows reuse. This is current source binding, not a semantic keyword rule.

Private checkout uses the existing parser, preview, revalidation and code-owned messages. Current private input bypasses both models; whole private history messages are excluded so an adjacent recipient name cannot survive phone redaction. Normal product names remain usable. Partial commits do not roll back a completed mutation or replay it on model failure; receipt/current-state acknowledgement, actual handoff or no-send owns recovery. Confirmation/handoff ends further model/effect work. The capture transport exercises the actual dispatcher and Meta adapter without opening a delivery socket; it is not live delivery/Pancake receipt evidence.

No production entrypoint imports the two candidate modules. One owner and one verifier remain, with bounded native continuation, mandatory verification of surviving final prose, current readback, no rewrite/reverify loop and no automatic provider retry. The provider runner registers seven outcomes (six public turns and one private code turn), N1, at most24generation requests, evaluator-only labels outside requests, exact runtime source/config hashes and all errors in the denominator. Actual source ETA mapping remains a disclosed limitation, never replaced with synthetic ETA in provider mode.

Final verification/source identities and the provider outcome are recorded in COMMANDS.md and CHECKPOINT_B.md after execution. Earlier intermediate results are not relabeled as clean-source proof. Actual sales quality, immutable provider versions, human acceptance and live activation remain separate from engineering integration.
