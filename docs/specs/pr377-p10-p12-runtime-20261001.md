## Project objective and ownership

Help the customer choose and buy an appropriate product through grounded advice,
without pressure, invented facts or invented transaction success. Producer
interprets the current customer input; Strategist chooses the answer/evidence and
one justified next step; Responder words the compiled task. Code owns verified
facts, calculations, authorization, persistence and receipts. An error handler
must not become a second Strategist or manufacture a transaction.

## P10: recovery after Responder failure

After a validated adaptive ANSWER task with SUPPORTED evidence, an empty
unrealized-evidence list, KEEP_OPEN and no canonical request, live runtime may
recover the already-selected facts when the Responder times out, returns malformed
JSON, omits the payload, returns an invalid shape, or fails the output guard.
It reuses the existing compiler and all source/subject/freshness/output checks.

A safe draft statement about an unanswered part is preserved when available.
When no trustworthy draft remains, or null prose cannot prove whole-question
coverage, recovery uses the existing bounded incomplete-answer sentence followed
by the verified facts. It does not parse `goal` into a new claim. This is an
explicitly incomplete answer, not a claim that every requested property was
answered. A specific missing property cannot reliably be named after losing the
only draft that named it; this remains a quality limitation for P11.

Recovery does not apply to missing evidence, action/checkout requests,
FIRST_CONTACT_FIXED, provider identity mismatch, caller cancellation, or frozen
evaluation. It adds no model call or network retry. The original failure stage
and machine reason remain observable, even when deterministic recovery succeeds.
The final outbound guard still validates the recovered output.

Before a Strategist task exists, the existing verified compatibility fallback
remains responsible for the reply. No plan is invented on behalf of the failed
Strategist. Independent verified media are not cleared by this change.

## P10: isolate lookup and persistence failures

Each failed requested business-fact read contributes an ERROR envelope with no
facts and a fixed machine reason. Other requested reads continue, in their
existing order and bounded concurrency. A failed price read cannot erase an
independent stock read or another product's verified price. No error envelope
can authorize a claim or a cart effect. Single-product resolution uses the same
boundary. There is no new retry policy or speculative data substitution.

A commit failure leaves the atomic state/Outbox boundary in charge. The runner
retries under its existing Inbox policy; it does not announce a receipt or mark
the batch complete from a planned reply. Durable retry/permanent-failure reason
fields retain bounded machine codes, not raw provider/database exception prose.
This reduces sensitive-data leakage without changing exception classes or
transaction retry counts. Model wording failures with usable facts complete via
fallback even on the last configured Inbox attempt.

## Existing quota and per-call observations

Whole-PR review found the opt-in C3 path bypassed the existing generation quota.
C3 now shares one quota reservation for the AI turn across Producer, Strategist,
Responder, validation retries and any legacy contribution. This preserves the
project's turn-based quota unit, not a new per-token/per-call budget. With C3 off,
legacy reservation behavior is unchanged. A denied or unavailable quota prevents
transport calls; trusted human-owner admission remains before quota and models.

The existing decision-event JSON may carry `c3ModelCalls`: actual transport calls
only, each with role, RETURNED/ERROR, elapsed transport milliseconds and nullable
prompt/output/thinking/total counts from provider usage metadata. RETURNED does
not mean valid JSON, guard pass, useful advice or successful business action.
Absent/invalid token counts remain null. The provider's total is retained as
reported, not recomputed by adding thinking again. Latency is transport latency,
not end-to-end conversation latency. Quota-denied attempts are not model calls.

The optional `c3Candidate.failureStage` distinguishes EVIDENCE, STRATEGIST,
RESPONDER and FINAL_GUARD. Successful recovery keeps VALIDATED plus its recovery
reason, rather than hiding the original failure. Legacy `modelCalled` and model
usage fields retain their old meaning; C3 consumers must use the new optional
field rather than assuming those legacy fields count all models.

No prompt, response body, URL, credential or provider error prose is added to
these telemetry fields. No database migration is required. Events still share
the existing atomic commit: a failed transaction does not separately persist
these observations. This is not a new billing ledger or a full telemetry service.

## P11 / P12 and rollback

provider A/B remain DEFERRED by the owner's earlier instruction. No scores or
model-quality claims are inferred from fakes, schema checks or fixture validators.
The corpus and rubric are unchanged; there is no new evaluation framework.

P12 includes source/spec review of the complete PR diff, regression verification,
and a documented residual list. It is same-agent self-review, not an independent
review. New-head CI and retained acceptance gates must pass before full-plan
acceptance; a previous head's green CI cannot certify this patch.

state transformation, data deletion or live switch is necessary. The previous
bounded recovery behavior returns on revert. No runtime flag is enabled here.
